# ADR-002: 使用自研显式状态表实现中央状态机

## Status
Accepted (2026-09-21)

## Background
开发书 §7 要求「一个中央状态机控制音频和动作互斥」，§7.1 给出状态集（自检/空闲/录音/思考/说话/表演/故障锁定）与迁移规则。硬需求：①「任意运动态 → 拔出/急停/串口超时 → 停机并锁定」是**抢占式**迁移；②「换角色时旧网络请求即使晚到也不能播放」（`session_generation`）；③状态机行为必须能被确定性单元测试穷举（非法迁移要有明确拒绝）。

## Decision
**自研显式状态表**：一张 `{trigger, source, dest, guard, action}` 的数据列表 + `can_fire()/fire()` 两个函数；`can_fire` 返回 `(ok, reason)`，非法迁移返回拒绝原因而非抛未捕获异常；`SAFETY_TRIP` 是唯一允许从 `*` 抢占的迁移；进入 `IDLE` 或切换角色时 `session_generation += 1`。

依据：状态 7 个、迁移约 14 条，规模下一张**表即规格**，可被测试直接穷举（含非法迁移）；抢占式安全迁移与 generation 语义能显式表达，无库内约定负担；无第三方依赖，减少供应链面。

**升级触发条件**：状态数 > 12、或出现并行域/历史态（如「配网」「OTA 进行中」并列子流程）时，迁移到 `python-statemachine 3.2.1`（MIT，2026-08-01）。其显式表可 1:1 映射，迁移成本低。

排除：`transitions 0.9.3`（MIT）——方法注入与条件顺序敏感，在安全联锁场景增加隐式面；`python-statemachine 3.2.1`——本规模下其复合态/历史态能力用不上，3.0 有过一次大改（`StateChart` 引入），MVP 不承担该升级面。

## Consequences
- 正面：状态机即数据，测试可穷举；无依赖；抢占式安全迁移与 generation 表达清晰。
- 负面：需自己实现「进入/退出回调」「状态名枚举」等边角；规模增长后需自主维护。
- 约束：所有迁移必须经 `can_fire` 校验；禁止在 `web/` 或 `ai/` 里直接改状态，只能发事件。
