0. 一句话定位与交付边界

本交付是「无硬件档位」的完整软件骨架：在普通电脑上、不接任何实物、不联网的条件下，把「按键 -> 录音 -> 识别 -> 对话 -> 合成 -> 说话 -> 动作 -> 记忆」的编排闭环跑通并可确定性回归。

它不是可上市的整机成品。本机实测只覆盖软件可复现部分（对应开发书第 20 章「样机源代码测试」一栏）；实物项按架构规格 §10.1 的 C1–C13 全部保留为「待验证」。本文档的 C 编号与 docs/architecture/00-architecture-spec.md §10.1 一一对应；开放决策编号（OD-x）与 docs/decisions/OPEN-DECISIONS.md 一一对应。

判定原则（贯穿全文）：模拟与格式检查不得替代实物证据。测试全绿只说明「软件逻辑正确」，不说明「整机就绪」。本阶段生产就绪评级为 Bronze（最低可上线档，非商业级）。

4. 已知边界（必须明示）

4.1 内容安全守卫是桩级：误拦边界（C13）与漏放边界（OD-8）

host/ai/safety.py 的「越界声称」检测基于词表 + 前后置锚，无法穷举所有合法叙事句式。这构成两条互补的已知边界，分别登记在架构规格与开放决策中——本节即 Spec §10.1 的 C13（误拦）与 docs/decisions/OPEN-DECISIONS.md 的 OD-8（漏放）的展开说明。实测证据来自 QA 复验的 held-out 集。

4.1.1 误拦边界 —— 对应 C13（fail-safe 方向，非安全漏洞）

第三人称具体人名 + 「已经」 + 完成收尾 -> 拦截。合法叙事句被拦下：

输入期望实际判定
小熊已经拿到了一颗糖ALLOWBLOCK（声称已完成现实操作: 已经拿到）误拦
小狗已经打开了门ALLOWBLOCK误拦
小兔子已经关好门了ALLOWBLOCK误拦
奶奶已经买好菜了ALLOWBLOCK误拦
老师已经寄出了信ALLOWBLOCK误拦
他已经关好窗户啦ALLOWALLOW（纯代词「他」，无具体人名）正确放行

4.1.2 漏放边界 —— 对应 OD-8（advisory，不重开 B3）

第一人称 + 替/帮 + 动作 + 「了」，但不含「把/将」，后置锚未命中 -> 放行：

输入期望实际判定
我替你转账了BLOCKALLOW（无「把/将」，后置锚未命中）漏放

4.1.3 怎么理解这两条边界（写给接手的人与决策者）

  • C13 的危害方向是安全的（fail-safe）：玩具会偶发拒说个别合法叙事句（如讲「小熊已经拿到糖」的故事），体验上有噪声，但不会漏放不当内容，也不会真去做任何现实动作（它没有能改变物理世界的能力）。属「桩守卫无法穷举」的已知成本，边界很窄（仅限具体人名），按 C12 接受；AI 模型接入后以真实审核替换（随 C12/C13 一并关闭）。
  • OD-8 是 C13 的互补方向：它不是本次引入的缺陷，而是锚设计既有的覆盖边界；处置是「收紧后置锚时增补『我 + 替/帮 + 动作 + 了』分支并补回归用例」，本阶段按 advisory 登记，不重开 B3 阻断。
  • 仍是桩级：两条判定都基于本地句式规则，非真实模型审核。真实内容安全的验收（C12）必须等真实模型接入后，用真实边界问题集重跑。
  • 不做的事：不为「把 C13 的误拦压到零」而放宽规则——放宽会同时扩大 OD-8 这类漏放面，方向错误。
