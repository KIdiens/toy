# 音频设备异常恢复

日期：2026-10-21。继续在交接版本 `f19d35a` 的工作区推进，未创建提交或推送。

## 复现与修改

修复前已复现三条失败路径：录音启动异常后仍停在 `RECORDING`；播放异常后仍停在 `SPEAKING`；结束录音时发生异常，没有发布结果唤醒网络线程。等待结束或关停时，没有录音的请求仍可能进入 ASR。

本轮补齐了失败上报和恢复路径：

- 录音异常也发布带操作身份的就绪结果；等待方收到原始异常，不再继续等完整录音超时。
- 新增领域事件与触发器 `AUDIO_FAIL`，只允许当前阶段匹配的录音或播放错误回到 `IDLE`，并递增会话代数。播放失败不伪装成 `PLAY_DONE`。
- 适配层在上报前检查操作身份及取消状态；旧操作错误不结束新操作，核心也不会因此解除 `FAULT_LOCKED`。
- 当前播放在角色切换后仍继续时，确认其身份后按当前代数上报失败，避免失败回执被当作旧消息丢弃。
- 失败、空录音和已经取消的请求不进入 ASR；正常取消不计作线程异常。实际设备错误仍保留日志与诊断计数。
- 设备恢复后，用户可以重新按键开始一轮；新录音清除旧错误，不会在后台自动重试或重复调用语音服务。

规格新增 AC-30，架构状态表同步增加音频失败迁移。外部状态枚举仍为原有 7 个状态，没有新增网页或外部服务配置。
