# PRD：可换公仔 AI 语音动作玩具 - 主机程序（toy/host/）

版本 v1.0　角色：产品经理 许清楚
状态：本 PRD 用于 Spec 冻结，落点目录 `toy/host/`。
约束前提：**无硬件（无树莓派 4B / ESP32 / MG90S / 独立电源）+ 无云端（不接阿里云百炼）**。

---

## 0. 一句话定义

本次开发的是开发书第 7 章定义的**完整主机程序**：一个在普通电脑上就能跑起来的中央编排系统——状态机、音频采集与播放、AI 路由、动作调度、SQLite 存储、网页管理与可视化编排。
硬件和云端**以"适配器 + 确定性替身"的形式预留接口但不实接**，从而在无实物条件下全部可运行、可确定性回归。

必须守住的诚实边界（引自开发书 0.1 / 附录 B / 验证记录）：
> 本项目提供的是软件骨架与可复现的软件验收，**不证明**固件编译烧录、真实舵机运动、真实机械装配、真实云端账号调用。无硬件预演"不是视频回放，也不是实物动作验收"。

## 1. 问题陈述

### 谁、在什么场景、什么痛点

**维护者（用户本人，DIY 开发者）**手上只有一份《开发书》+ 两个起步 CLI（`motion.py` 四轴动作播放、`cloud_chat.py` 千问单轮问答）。开发书第 7 章描述的完整主机程序——中央状态机、音频、AI 路由、动作调度、SQLite、网页编排——**一行都还没实现**。

- **现状怎么解决**：靠两个孤立 CLI 分别跑动作和问答，中间没有任何编排：没有状态机、没有取消、没有角色切换、没有记忆、没有工具调用、没有网页。
- **为什么不行**：
  1. 孤立 CLI 无法表达"按键→录音→识别→对话→合成→说话→动作"的**互斥与取消**关系（录音时要停电机、换角色要废弃迟到回复）；
  2. 硬件与云端都还没到货/不能接，若把主机写成"直接调串口 + 直接调百炼"，则**今天没有任何一行能运行、能测**；
  3. 开发书第 9/11/13 章的关键规则（安全联锁、末帧保持、记忆删除、角色匹配）目前没有任何代码承载，**规则只活在文档里**。

### 真实需求（不是用户嘴上说的方案）

用户嘴上说"实现完整主机程序"，真正的需求是：
> **在买不到硬件、不能接云端的当下，先拿到一套"能跑、能测、有确定性证据"的主机骨架，并且日后插上真硬件、接上真云端时，只需替换适配器而不改编排逻辑。**

因此核心设计取舍是：**把"会变化的外部世界"（串口硬件、云端 AI、声卡）全部收敛到三个可替换的适配器接口后面，MVP 全部用确定性替身跑通。**

## 2. 目标用户

| 画像 | 是谁 | 关心什么 | 对产品的要求 |
|---|---|---|---|
| **使用者：儿童（3–8 岁为主）** | 玩具的交互主体 | 会说话的伙伴、会动的公仔、按一下有反应 | 零学习成本；按键即可；不识字也能玩；拔插公仔不伤手；不需要做任何设置 |
| **决策者/付费者：家长** | 出钱、担责、管合规 | ① 内容适龄 ② 隐私（录音去哪、能否删、是否上传）③ 费用可控（不能订阅陷阱/超支）④ 物理安全（夹手、断电）  ⑤ 不能误触恢复出厂 | 默认最小化采集；**可见/可删/可关**；费用有硬上限；夜间不主动发声；静音是真停采集；管理动作要二次确认 |
| **维护者：用户本人（DIY 开发者）** | 装机、调试、后续接真硬件/真云 | 无硬件可跑、确定性可回归、协议可回放、换硬件只改适配器、日志可诊断 | 一根命令跑全部测试；失败可复现；安全默认关（未 ARM 不动电机）；配置与密钥分离 |

### 3.2 三类关键事实（团队 Lead 指定方向）

**事实一：它们在"没有实物硬件时如何演示软件"**

| 做法 | 谁在用 | 说明 |
|---|---|---|
| **仿真优先 + 同一套代码** | Reachy Mini（最典型） | 官方明确"无硬件也能开发"：`docker-compose --profile vnc up` 起 MuJoCo 仿真，浏览器打开 3D 预览，REST API 在仿真与真机间切换，**控制代码完全一致**。|
| **浏览器物理模拟器** | Petoi Bittle | urdf-loaders + rapier.js + three.js，左边控制模型、右边物理模型，WASD 可驱动。|
| **积木先跑虚拟板** | sheenbot 的 MakeCode | 明确主张"先在浏览器仿真里跑通积木再碰硬件""预算紧张就先用免费的仿真"。|
| **只有宣传视频/众筹页** | Ropet / Loona / EMO / 乐森 | 缺乏可离线复现的仿真，正是差评来源——"广告里的宠物 vs 地板上的现实"。|

> **对本项目的结论**：我们的"无硬件验证"不是自创，而是跟随 Reachy/Petoi 的**仿真优先**范式。
> **但层级不同、必须诚实标注**：Reachy 模拟的是**物理动力学**，我们模拟的是**MCU 协议对端**（in-process 替身）。因此替身只能证明"主机侧协议/时序/联锁/取消逻辑正确"，**不能证明固件与机械**。这条边界写进验收（见 §7）。

**事实二：动作编排工具的交互形态——关键帧时间线 vs 积木式**

- **关键帧时间线**：乐森 Robosen Mini（"define joint positions at specific timestamps, and the firmware interpolates"）+ Robosen Studio（拖、放、点，一键生成整套动作）。这是**表达型/文艺类动作机器人**的主流形态。
- **积木式（Blockly / Scratch）**：Loona、Petoi CodeCraft、LEGO、Sphero、MakeCode。偏向**编程教育**语境。
- 与本项目的关系：开发书第 13 章明确"**先做关键帧时间线，再考虑 Scratch 式积木，第一阶段不必同时开发两种编辑器**"。
> **结论**：MVP 采用**关键帧时间线**；积木式编辑器列入 Backlog（P2），不占 MVP 工期。

**事实三：长期记忆的透明度做法与用户差评**

- **透明度做法**：做得好的是"本地处理 + 完全离线"（Ropet 日常行为本地模型、Moflin 全本地音频、Eilik 无联网无摄像头）。做得差的是"有隐私面板但看不懂/删不净"。
- **家长差评/担忧（真实证据）**：
  1. Common Sense Media：83% 担心数据收集；**42% 希望完全不存储**；多数人不接受"只有隐私条款、没有可见可删的界面"。
  2. 2025–2026 测试发现某 AI 玩具**泄露数万条儿童聊天记录**（含姓名、生日、家庭细节）。
  3. Ropet 案例：即便厂商反复强调隐私，家长的焦虑来自"**它是否需要记录这么多**"——家里长期存在一个"看着你"的设备，会被感知为监控而非陪伴。
  4. 典型差评（开发书第 19 章同款）：**"删了还记得"**——模型删了记忆但短期历史/摘要/其他档案缓存仍在引用。
> **结论**：记忆功能的产品要求不是"能记住"，而是"**默认最小化 + 可见 + 可删 + 删后清上下文 + 默认访客不持久 + 录音处理后可删**"。透明性必须做成界面里的查看/删除/关闭按钮，而不是藏在隐私条款里。

## 4. 我们的差异化

1. **无硬件、无云端也能完整运行的编排内核**：业界同类（除开源 Reachy/Petoi）都把软件绑死在自家硬件 + 云上。我们把硬件（串口）、云端（AI）、声卡三处外部依赖全部收敛到适配器接口，MVP 用确定性替身跑通——**今天就能测，明天换真件只改适配器**。
2. **诚实的分层证据**：明确区分"软件可复现证据"与"实物/云端证据"，不拿仿真冒充实测（这正是开发书 0.2、第 20 章、验证记录反复强调的）。
3. **把家长最怕的隐私做进默认值**：记忆默认只存用户确认过的事实；录音处理后可删；有可见可删可关的记忆界面；夜间不主动出声；静音是真停采集。对照 Common Sense Media 的"42% 想不存储、要可查看可删"。
4. **关键帧时间线编排 + 安全检查前置**：编排先校验（限位、速度、角色匹配），无硬件先离线预演，与乐森 Studio 一致的交互心智，但不依赖私有平台。

## 5. MVP 范围与不做项

### 5.1 三个适配器（本 MVP 的结构性前提）

MVP 的全部"无硬件、无云端"能力，靠把外部依赖收敛到三个接口实现。**真实现写接口但默认不启用；MVP 用确定性替身**：

| 适配器接口 | 真实现（预留，默认不启用） | MVP 替身（确定性） | 替身能证明 / 不能证明 |
|---|---|---|---|
| `MotionTransport`（串口对端） | 真串口 `serial.Serial` 连 ESP32 | **In-process MCU 模拟器**：用 Python 复刻 `motion_controller.ino` 的 STATE/ARM/FRAME/STOP/SETTLED/FAULT、200ms 角色稳定、300ms 看门狗、1400–1600μs 安全窗、每 20ms 每轴 ≤6μs 爬升 | **能**：主机侧协议客户端、联锁处理、超时/故障停机、末帧保持、角色匹配；**不能**：固件真实行为、真实机械 |
| `ChatBackend`（AI 路由） | 真 Qwen ASR/对话/TTS（HTTPS，需 key，默认关闭） | **确定性桩后端**：基于固定夹具返回预设文本与"工具调用"请求；不发起任何网络请求 | **能**：状态机、路由、工具白名单、审核挂钩、会话失效；**不能**：真实识别/生成质量 |
| `AudioIo`（声卡） | 真 `arecord`/`aplay` 或 sounddevice | **文件后端**：录音 = 读固定夹具 WAV；播放 = 写文件/空设备 | **能**：录音→识别→合成→播放编排、音量状态、半双工互斥；**不能**：真实声卡延迟/回声 |

> 未设置 `DASHSCOPE_API_KEY` 时，`ChatBackend` 必须自动落到桩后端并可运行——**这是 MVP 的硬要求**（无云端可跑）。

### 5.2 纯软件可验证功能清单（每项说明"无实物如何证明成立"）

| 编号 | 功能 | 无硬件/无云端如何证明成立 |
|---|---|---|
| M1 | 中央状态机（空闲/录音/思考/说话/表演/故障锁定）与合法转换 | pytest 驱动假时钟走全部转换；断言非法转换被拒、录音时停电机、任一步可取消、故障后必须人工确认才回空闲 |
| M2 | MCU 协议客户端 + In-process MCU 模拟器 | 同一套协议测试同时跑"真实现接口"与"模拟器"；用开发书第 9 章语义构造确定性对局：未 ARM 不动、错角色不 ARM、300ms 无有效帧停 PWM、SETTLED 后保持 150ms 再 STOP |
| M3 | 动作时间线 + 限位/速度校验 + 离线预演 | 纯函数单元测试（数值有限、时间递增、1400–1600μs、s(u)=3u²−2u³ 峰值速度 ≤300μs/s、首末帧中位）+ 无硬件 `--dry-run` 打印脉宽轨迹（已由 `motion.py` 现成覆盖，搬入 `host/motion` 并扩充） |
| M4 | SQLite 长期记忆（profiles/memories，查看/删除/单条/清空/关闭） | 临时库跑写入→关闭连接→重开连接（模拟重启）断言可读；删除后**新建会话**断言不再注入；断言开启外键、全部查询参数绑定 |
| M5 | 角色注册与切换（role_id 1/2/3、配置、session_generation） | 单元测试：切角色时 `session_generation` 自增；旧 generation 的"迟到回复"被丢弃；动作播放前校验 role_id 与当前一致 |
| M6 | AI 路由 + 后端适配器（真云适配器 + 确定性桩） | 默认无 key → 桩后端；断言零网络出口；断言桩返回的"工具调用"被本地白名单二次校验后才执行 |
| M7 | 工具白名单本地执行（get_weather/create_reminder/play_content/play_action/cancel_reminder） | 桩后端产出工具调用；断言参数越界/未知工具被拒；断言"只有数据库事务成功才回'已设置'"；`get_weather` 无 key 时明确返回失败而非编造 |
| M8 | 提醒任务（持久化、时区、幂等） | 假时钟推进到 due_at，断言只触发一次（幂等键）；重启后不重复触发；时间不可靠时暂停绝对时间提醒并提示校时 |
| M9 | 本地内容库 + 本地表演（音频+动作统一单调时钟） | 文件音频 + 动作时间线在同一单调时钟下采样；断言断网（桩后端抛错）仍可播放；断言"按经过时间采样"而非"每帧 sleep 累加" |
| M10 | 音频抽象层（真后端 + 文件后端） | 文件后端跑录音夹具→识别→合成→播放全链路；断言半双工互斥（说话时不监听） |
| M11 | 网页管理 + 可视化关键帧编排（validate/play/stop/import/export） | FastAPI TestClient：断言校验接口不触发硬件、播放接口要求 role_id 匹配、stop 立即取消队列、连续两个播放请求按规则拒绝/替换而非叠加 |

## 7. 验收标准（Given / When / Then）

以下全部为**软件可复现验收**（无硬件、无云端），对应开发书第 20 章中"样机源代码测试"一栏，**不替代**实物证据。

**A1 状态机合法性（M1）**
- Given 状态机处于"录音"，When 收到"表演键"，Then 先取消录音并删除临时录音、不停留在录音态（按开发书 5.2 录音态"表演键=取消录音"）。
- Given 状态机处于"故障锁定"，When 未收到人工确认，Then 永不自动回到"空闲"或重新解锁电机。
- Given 任意运动状态，When 触发拔出/急停/串口超时，Then 进入"停机并锁定"。

**A2 MCU 协议与联锁（M2）**
- Given 模拟器未 `ARM`，When 主机发送 `FRAME`，Then 模拟器返回 `ERR FRAME` 且不产生 PWM 目标。
- Given 期望角色 1，When 模拟器识别角色 2，Then 主机不得发送 `ARM`（对应 `test_wrong_role_never_arms`）。
- Given 主机持续发 `FRAME`，When 模拟器 300ms 内无有效帧，Then 停机并上报 `FAULT INTERLOCK_OR_TIMEOUT`。
- Given 末帧已到达，When 收不到 `SETTLED`，Then 主机 2 秒内报错停机，`finally` 必发 `STOP`（对应 `test_missing_settled_stops`）。
- Given 末帧目标已确认，Then 主机保持 ≥150ms 再 `STOP`（对应 `test_final_frame_is_held`）。

**A3 动作校验（M3）**
- Given 脉宽 1399/1601/NaN/Inf/布尔/字符串，When 校验，Then 全部 `ValueError`。
- Given 时间非严格递增，或峰值速度 >300μs/s，When 校验，Then 拒绝。
- Given 合法动作，When 无硬件预演，Then 全程四轴保持在 1400–1600μs、首末帧为 1500。

**A4 记忆（M4）**
- Given 已确认"喜欢恐龙"写入 profile，When 关闭并重开数据库连接，Then 可读回该已确认记忆。
- Given 删除某条记忆，When 新建会话构建上下文，Then 该事实不再出现在注入上下文中（含短期历史与摘要缓存）。
- Given 关闭记忆开关，When 用户说"记住……"，Then 不写入。

**A5 角色切换竞态（M5）**
- Given 角色 1 正在等待 AI 回复，When 切换到角色 2，Then 角色 1 的迟到回复不播放、`session_generation` 已自增。
- Given 网页请求携带旧 role_id，When 当前角色已变更，Then 播放请求被拒绝（对应开发书 13.2）。

**A6 AI 路由与桩后端（M6）**
- Given 未设置 `DASHSCOPE_API_KEY`，When 启动与对话，Then 使用桩后端运行、**零网络出口**、不报致命错误。
- Given 桩后端返回"调用 get_weather"，When 参数非法，Then 本地拒绝且不编造天气。

**A7 儿童边界（M14）**
- Given 一条将被播放的模型输出，When 输出审核判定不合格，Then 在**合成/播放之前**拦截，绝不"先说出来再撤回"。
- Given 涉危险现实操作的问题，Then 使用固定模板引导找成年人；Given 索要住址/学校/密码，Then 固定拒绝。

**A8 编排接口（M11，属 Backlog 但验收需先定义）**
- Given 非法动作包，When 调 `/api/actions/validate`，Then 返回拒绝且不触发任何硬件动作。
- Given 已有播放中的时间轴，When 收到第二个播放请求，Then 默认拒绝或显式替换，**不静默叠加**。
- Given 含 `../`、绝对路径、符号链接、超量文件或高压缩比的 zip，When 导入，Then 全部拒绝，且失败保留旧版本。

## 8. 边界条件（五态 + 资源约束）

| 类别 | 要求 |
|---|---|
| 空状态 | 无角色/无记忆/无内容时，界面给"首次使用引导 + 快速开始"，不出现空白页或空洞占位文案 |
| 加载态 | 识别/对话/合成各阶段有进度与可中止入口；不承诺固定 2 秒（开发书 10.4） |
| 错误态 | 网络失败 → 本地提示音 + "网络暂时不可用"；桩后端异常 → 不可致命崩溃；分类错误（模型/网络/权限/参数） |
| 边界值 | 脉宽 1400–1600μs；动作时长 ≤60s；帧数 2–1000；录音单次 ≤15s；单次回复长度上限；每日次数与费用上限 |
| 并发 | 第二个播放请求默认拒绝/显式替换；录音与播放半双工互斥；数据库写用事务 + 幂等键 |
| 离线 | 断网仍可：本地动作、本地内容、已确认记忆读取、时钟有效时的提醒；不可：AI 对话（明确提示） |
| 权限拒绝 | 网页管理默认只绑 `127.0.0.1`；开放局域网需登录；写操作需防 CSRF；配网密码不回显、不入普通日志 |
| 时间不可靠 | 冷启动无网络无法确认时间 → 暂停绝对时间提醒并提示校时，不静默错发 |

## 9. 儿童模式边界（硬性）

1. **双层审核**：用户输入审核 + 模型输出审核；**输出审核必须在音频开始播放前完成**，流式也要按完整语义段审核后再合成，不能先说出来再撤回（开发书 15）。
2. **工具白名单**：模型只能申请白名单动作 ID 与工具；禁止任意 URL、任意命令、任意脉宽（开发书 2.2、9.3）。
3. **记忆默认最小化**：只存用户明确确认的名字/昵称/兴趣/语言偏好；默认访客不持久；删除后清理会话缓存与摘要；提供查看/删除单条/清空/关闭/导出（开发书 11.3）。
4. **夜间与静音**：夜间不自动动作、不主动开口；静音时**真正停止采集**，不是只停止发送；录音时设备有可见指示（开发书 15）。
5. **物理与安全文案**：涉危险现实操作引导找成年人；螺丝/磁铁/弹簧/电池不可轻易脱落（实物阶段由架构师/硬件侧承接）。
6. **恢复出厂二次确认**：放在有再次确认的管理界面，避免孩子误操作（开发书 5.2）。
7. **不索要隐私信息**：固定拒绝模板，不索要住址、学校、密码（开发书 10.3 提示词已内置此条，需在代码层强制而非仅靠提示词）。

## 11. 数据埋点方案（PRD 必含）

MVP 埋点目的：验证"无硬件无云端闭环"是否真的按设计跑通，并为日后接真件提供基线。

| 事件类别 | 必埋事件 | 说明 |
|---|---|---|

| 激活 | `first_core_action`（首次完成一次按键对话闭环） | 产品假设：闭环能端到端跑通 |
| 状态机 | `state_transition`（from/to/trigger）, `session_generation_bump` | 验证互斥、取消、换角色竞态 |
| 动作 | `action_validate_result`, `action_play_start`, `action_settled`, `action_fault` | 验证校验与联锁；埋点须含 role_id、是否 dry-run |
| AI 路由 | `ai_backend_selected`（stub/real）, `tool_call_requested`, `tool_call_rejected` | 验证无 key 时零网络出口 |
| 记忆 | `memory_written`, `memory_deleted`, `memory_scope_closed`, `memory_session_cleared` | 验证"删了不再引用" |

| 异常 | `error_occurred`（前端 + API + 状态机分类） | 失败可诊断 |

## 13. 给下游的最小交接（架构师 / 设计师）
