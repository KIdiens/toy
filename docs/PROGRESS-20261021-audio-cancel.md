# 录音提前结束与播放打断

日期：2026-10-21。继续在交接版本 `f19d35a` 的工作区推进，未创建提交或推送。

## 问题与复现

audio 队列只有一个消费者。原先 `record()` / `play()` 会阻塞消费者，随后到来的 `RECORD_STOP` / `STOP_AUDIO` 只能排队，无法结束正在执行的操作。两个从真实按键入口触发的回归，在修复前均因“停止后 0.5 秒内录放音仍未结束”而失败。

此外，声卡的便捷录音 API 预先分配完整时长的缓冲区，提前停止后不能把整块缓冲区当作已采集的样本；旧播放完成事件也不应结束刚开始的新录音。

## 实现

- `AudioControl` 在命令入队时为每次录音、播放分配独立取消事件。结束命令立即置对应事件，然后保留原来的命令消费顺序。这里不调用声卡 I/O。
- 停止录音与停止播放分别作用于自己的事件；较旧代数的停止命令不取消更新的操作。同一代数重新开始录音时，仍分配新事件。
- 网络线程同时检查录音代数与操作事件，等待当前录音完成；队列中尚未开始的录音不会被误判成“没有录音”，同一代数的上一段录音也不会被注入新请求。
- `SoundDeviceBackend` 使用输入、输出回调流。停止后由音频线程中止并关闭自己持有的流，录音结果只包含实际收到的采样帧及对应时长。流构造后取消、启动失败、缓冲错误和完成信号超时均有清理路径。
- 播放取消与异常均清理播放器的忙标志；取消不计为整段播放完成，也不投递 `PLAY_DONE`。
- 关停时先发出取消信号，再等待领域线程退出。模拟 MCU 配合真实声卡时，播放后不再额外等待模拟说话时长；空音频的模拟等待也能被取消。

声卡启动参数沿用上一轮的 `--audio sd`、输入/输出设备及采样率设置，没有增加网页或外部服务配置。

## 证据边界与后续

本轮未采集本机麦克风，也未向真实扬声器播放声音。上述停止时间、样本数量及流收尾结论来自设备替身；驱动实测时延、音质、热插拔、长时间运行及机械同步仍待真实设备验收。真实云 ASR/LLM/TTS 也未接入，C6、C9 等实物项继续待验证。
